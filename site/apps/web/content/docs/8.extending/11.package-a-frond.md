---
title: "A frond in a package"
description: "Publish a frond on npm, install it with one line, and put your own classes in it."
kind: "extending"
---

A frond can live in an npm package, the way a reusable app lives in a Django project. The package
brings the code that does not change from one project to the next. What does change is left as a
[port](/docs/concepts/port), and each project fills it in.

## Write it

The package exports a function that returns its frond. Its name is the last segment of the package
name: `@acme/mail` exports `mail`.

```ts
// @acme/mail — src/index.ts
import { frond } from '@fougere/core';

/** How a mail leaves — the package does not choose. */
export abstract class Mailer {
  abstract send(to: string, text: string): Promise<void>;
}

export class MailService {
  constructor(private mailer: Mailer) {}

  welcome(to: string) {
    return this.mailer.send(to, 'Welcome!');
  }
}

export class MailHandler {
  constructor(private service: MailService) {}

  welcome(to: string) {
    return this.service.welcome(to);
  }
}

export const mail = () => frond('mail', {
  providers: [{ ctor: Mailer, deps: [], abstract: true }, { ctor: MailService, deps: ['Mailer'] }],
  handlers: [{ ctor: MailHandler, deps: ['MailService'], operations: { welcome: { params: { to: 'string' } } } }],
});
```

`MailService` knows what to send. `Mailer` is how it is sent — Resend, SMTP, Postmark — which only the
project knows. A package that has a sensible default ships one too (`class SmtpMailer extends Mailer`),
and the frond then works on its own.

## Use it

```bash
pnpm add @acme/mail
```

```ts
// fougere.config.ts
fronds: {
  '@acme/mail': {},
},
```

The frond answers under its key, `@acme/mail`. If the package ships no `Mailer`, the boot refuses and
says what to write — `MailService asks for Mailer, a port nothing in the frond '@acme/mail' realizes.
Extend it…` — rather than failing at the first mail.

## Put your own class in it

Extend the frond, and write the class the package leaves open:

```ts
// fougere.config.ts
fronds: {
  '@acme/mail': {},
  mail: { extends: '@acme/mail' },
},
```

```ts
// fronds/mail/services/ResendMailer.ts
import { Mailer } from '@acme/mail';

export default class ResendMailer extends Mailer {
  async send(to: string, text: string) {
    // call Resend
  }
}
```

`mail` serves the package's operations, and builds the package's services itself — so the
`MailService` of the package is handed your `ResendMailer`, even though the handler never asks for a
`Mailer` directly. It is the same rule as any port: a class that extends `Mailer` in the frond takes
its place. A class of yours replaces the package's default the same way.

Another frond reaches it through the package's handler, like any neighbour:

```ts
import type { MailHandler } from '@acme/mail';

import type { Facade } from '@fougere/core';

class SignupHandler {
  constructor(private mail: Facade<MailHandler>) {}
}
```
