A frond can live in another repository, with its own team and release cycle. Your app still calls it; what has to travel is its contract, never its code.

## Where the code lives

A Frond can also move to a separate repository and remain available through `fronds:`.
Three things are called "together" and only one is mandatory: the **contract** must
travel, the **code** need not, the **ports** must reach each other.

Two commands cover the contract, depending on what you want to share:

| | What it does | When |
|---|---|---|
| [`fougere sync`](/reference/cli#fougere-sync-consume-a-remote-frond) | asks the host for `rpc.discover` and rebuilds its entities locally | the host is running; also the only way in for a Frond written in another language |
| [`fougere build-frond`](/reference/cli#fougere-build-frond-publish-a-fronds-entities) | compiles `entities/**` into an installable package | you publish the contract as a dependency |

The Frond's source code crosses in neither case. What stays open is the **ports**: see
[Deployment](/docs/run/deploy#splitting-in-production).

## Facts across repositories

Two things stop at a repository boundary, and only one of them is `fronds:`.

**Finding the listeners.** When the other team's Frond has an address in your `fronds:`, its
card says what it listens to, and the fact reaches it as a call — nothing more to write. A
call keeps nothing, though: a listener that is down misses the fact. When that matters, or
when the far side has no address you can call, a carrier goes under the emission — `onEmit`
hands the fact to a name, and the far side subscribes to that same name from its own code.
Neither reads the other; they meet on a string derived on both sides.

```ts
const app = await createApp({
  root: import.meta.dirname,
  createContainer,
  onEmit: (fact, payload) => publishToYourBroker(fact, payload),   // out
});

// in — the same local dispatch, validator and links included
await app.deliver(fact, payload);
// and what to subscribe to, read off your own signatures
app.listensTo();                                                   // ['postPublished']
```

**Knowing the shape.** The card publishes it: a frond's `facts` list carries every
`Emit<T>` its handlers inject, so `fougere sync` writes the class instead of a subscriber
copying the fields by hand. Re-export it into one of your fronds and an arriving fact is
validated against the emitter's own declaration.

A carrier has no address, and that is the line between the three words. `Emit` announces a
subject and `Fact` receives one, so neither names anybody — a carrier can take them across.
A `Pipe<T>` — the op that FINISHES a fact — is CALLED: it has an address, local or named in
`fronds:`, and
it answers. So a link crosses a process and never a carrier, which is the same line `Emit<T, A>`
draws.

See [emit-multirepo](https://github.com/chok/fougere/tree/main/demos/emit-multirepo) — two
projects, one fact, and the first publication lost on purpose to show what a carrier buys.
