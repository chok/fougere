## Create it

```bash pm
npm create fougere
```

The project is written for the package manager that ran the command — see
[the CLI](/reference/cli#which-package-manager). Then:

```bash pm
npm install
npm run migrate   # fougere migrate --latest --apply — create what the entities declare
npm run dev       # read the fronds → check the schema → seed → serve on :3000
```

The last lines `fougere new` prints are already written for your package manager. The boot log says
how many fronds it found:

```
INF [boot] ready in 483ms — 3 frond(s)
```

::note
**Alpha.** The `@fougere/*` packages are on npm under the `alpha` tag: the version is the whole
promise, and the surface can still move. This site and `demos/nuxt-blog` are complete references.
::

## What you get

A Nuxt app, a `fronds/` directory and one config file:

```
my-app/
  fougere.config.ts       ← database, auth, where each part runs
  fronds/
    blog/                 ← one domain of your app
      entities/Post.ts
      handlers/PostHandler.ts
      services/CurrentUserCollector.ts
      seeds/Post.seed.ts
    user/                 ← another one
      entities/User.ts
  apps/
    nuxt/
      nuxt.config.ts      ← modules: ['@fougere/nuxt']
      app/pages/          ← ordinary Nuxt pages
```

Each directory under `fronds/` is a [frond](/docs/concepts/frond): one domain, with its data and what
it does. The folder a file sits in says what it is — an entity in `entities/`, a handler in
`handlers/`, a service in `services/` — and nothing is registered by hand.

A page imports from a frond by its name:

```ts
import Post from '@fronds/blog/entities/Post.js';
```

The `@fronds/blog` name exists on its own, for every frond: no `package.json`, no workspace entry. To
give a frond a name other than its directory's, see [How the scan reads a project](/docs/extending/scan).
`fougere new` puts the app under `apps/<name>/` and the fronds at the root of the workspace, so
several apps can share the same fronds.

## The config it writes

```ts
// fougere.config.ts
import '@fougere/adapter-sql';
import { defineFougere } from '@fougere/core';
import { betterAuth } from '@fougere/auth-better';
import User from './fronds/user/entities/User';

export default defineFougere({
  sources: {
    main: { type: 'sqlite', path: '.data/app.db' },
  },
  fronds: {
    auth: betterAuth({
      user: User,
      secret: process.env.AUTH_SECRET!,
      baseUrl: process.env.SITE_URL ?? 'http://localhost:3000',
      basePath: '/auth',
      providers: { credential: { minPasswordLength: 8, autoSignIn: true } },
    }),
  },
});
```

- `sources:` — where rows live: [SQLite or Postgres](/docs/data/sql). With none, rows stay in memory
  and the boot says so.
- `fronds:` — the auth frond: [Authentication](/docs/access/authentication). The same key places a
  frond in another process: [Configuration](/docs/concepts/configuration).

Every key, with what answers it: [fougere.config.ts](/reference/config). To learn the rest by building
a blog, follow the [tutorial](/tutorial/1-crud).
