---
title: "Mirror a source you cannot query"
description: "A local copy of rows behind an API, refreshed from a mark."
kind: "task"
uses: ["repository"]
forms: ["Mirror<T>"]
---

A real database is queried where it is. `Mirror<Shape>` is the answer for a source with
no algebra: an HTTP API, a partner's catalog, a Frond behind a wire. The subclass supplies
one thing, the pull:

```ts
// services/PartnerCatalog.ts
export default class PartnerCatalog extends Mirror<BookCard> {
  async *pull(since?: Date) {
    for (let page = 0; page !== null; ) {
      const body = await fetch(`${api}?page=${page}&since=${since?.toISOString() ?? ''}`);
      const { items, next } = await body.json();
      yield items.map(toCard);
      page = next;
    }
  }
}
```

It is a [`Repository<BookCard>`](/docs/concepts/handler) that fills itself: the copy reads like any
rows, `this.list()`, and a handler extending it serves the copy and `refresh`. Everything around
the pull is the same for every mirror and lives in the base: `refresh(since?)`
pulls from the mark it is handed and writes each page in one `upsertAll`. The mark is the
caller's: it read one off its own rows, and it moves it only once a pass has returned — a
pass that threw halfway must not advance it past what the source changed in the gap.

A page is judged where every other row is, by the storage guard, strictly: a partner
renaming `label` would write nulls in silence otherwise. A refused page stops the pass; what
earlier pages wrote stays, because an upsert is idempotent and the next run resumes from
the mark.

It does not schedule itself. A boot hook, a cron, an operation behind a facade are all
legitimate and none of them is this class's business.

::note
`Mirror` has no directory of its own in the Frond vocabulary — a `mirrors/` folder is not
scanned. Place it in `services/`, where nothing
serves it, or extend it from a handler to serve the copy.
::
