# Add Fougere to an app you already have

You keep your app as it is: routing, pages, components, styling and server routes stay in
place. Fougere only adds its own paths: `/_fougere/call`, the one endpoint your pages call,
and `/_fougere/session`; `/auth/**` and `/api/me`, which answer once you turn auth on; and
`/api/{frond}/…` and `/graphql` if you turn [REST or GraphQL](/docs/infra/surfaces) on.

## The three pieces

**1. The module** — in your existing `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  modules: [/* your modules */, '@fougere/nuxt'],
});
```

**2. The config** — `fougere.config.ts` at the root
([full reference](/docs/getting-started#fougereconfigts--reference)):

```ts
import { defineFougere } from '@fougere/core';

export default defineFougere({
  db: { dialect: 'sqlite', path: '.data/app.db' },
});
```

**3. A first Frond** — one entity and one handler, under `fronds/` in the app you already have:

```
fronds/todo/entities/Todo.ts
fronds/todo/handlers/TodoHandler.ts
```

Fougere knows what each file is from the folder it sits in. A page imports the entity with
`import Todo from '@fronds/todo/entities/Todo.js'`: the alias exists on its own, so you add
no `package.json` and no workspace entry. A second domain later goes in `fronds/billing/`,
next to this one.

Run `pnpm dev` and check the log: `ready in … — 1 frond(s)`.

## Migrate feature by feature

Move one feature at a time, while your old routes keep serving the rest. Here is what
each thing you maintain today becomes:

| You maintain today | It becomes |
|---|---|
| a Zod/Yup schema | the entity's fields — [shape axis](/docs/schema/entities) |
| a table definition or additive migration | derived — `fougere migrate` writes it from the same fields; destructive changes stay explicit |
| `server/api/todos.post.ts` + validation call | a [handler](/docs/business/handlers) operation, validated before your code runs |
| form state + client-side rules | [`useFormFor(Todo)`](/docs/client/forms) — same validation as the server |
| `useFetch('/api/todos')` + refresh bookkeeping | [`useQuery(todo, 'list')`](/docs/client/queries-commands) — typed by the handler, revalidated by commands |

Delete the old files as each feature moves over: the goal is fewer files to keep in sync,
not a second copy.

## What stays yours

- **Pages and components** — Fougere adds composables, not components: no layout, no widgets.
- **Other server routes** — anything outside the paths above is left alone.
- **Auth** — optional. Keep your own system if you have one; `useCurrentUser` and the
  session-to-handler flow need [Fougere auth](/docs/client/session) to be enabled.

## Current limits

- The packages are on npm under the `alpha` tag: the version is the whole promise.
- Storage is SQL (SQLite, Postgres, MySQL or SQL Server, through Kysely), and its tables are
  written by `fougere migrate`. Fougere owns an entity's table: move a feature over when you
  can hand its table to Fougere, and keep your existing database code for the rest.

## Another host?

This page is about Nuxt because its module does the mounting for you. The same Frond runs
under Next, TanStack Start, React Router, SvelteKit and Express — three of them need no
package of their own. See *[Hosts](/docs/infra/hosts)*.
