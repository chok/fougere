The framework declares a few ports of its own, and they are extended with the same two
lines. They differ from yours in one way, which decides the rest: **their realization is
handed in, not scanned** — `storageFactory` builds one storage per entity, and no class
declares it. So a class extending one can only stand in front of it.

| | what it is | what a link sees |
|---|---|---|
| `Storage` | where an entity's rows live | every read and write, per entity |

`Storage` is the only one today. `Transport` is **not** extendable this way: a link is
recognized by its prototype chain, so a host port has to be a class, and `Transport` is a
function type. It has its own way in, one section down, and so does HTTP.

```ts
// services/Auditing.ts — in front of EVERY entity's storage
import { Storage } from '@fougere/core';

export default class Auditing extends Storage {
  constructor(private inner: Storage) { super(inner); }

  override async create(row: Record<string, unknown>) {
    await ship(row);

    return this.inner.create(row);
  }
}
```

[Every gesture](/docs/extending/source-adapter#the-gestures) is the port's, and this one writes one. What a link does not override reaches the next
one through the base — so a link is as small as what it changes.

It names no entity: `Storage` is the host port, so one class is in front of every entity of **its
own Frond**. `ports: { Storage: ['Auditing'] }` states the chain when there are two, exactly
as above.

The scope is the Frond and no key widens it, because the scope **is** the location: a link
sits beside the code it changes, and goes where that code goes. That is what keeps the
[gradient](/docs/concepts/configuration) true — a Frond moved behind `fronds:` would otherwise
silently leave the reach of a link its own code never mentions. A link that must be
everywhere is a **Frond** that is everywhere, which an extension already brings.

::note
The judge stays outside the chain. A row the entity refuses never reaches a link at all —
it is refused at the facade, and what a link receives is the value the schema already parsed.
::

### Reaching a transport, and an HTTP router

Neither is a host port, and neither leaves you without a way in.

A **transport** is swapped whole, by the host that boots the app — the same place `fronds:`
is read, because how a call travels is a deployment fact:

```ts
boot({ root, createContainer, remoteTransport: (url) => mySocketTransport(url) });
```

And an outgoing call to a Frond behind `fronds:` already runs through the app's
middlewares before it reaches the wire, so retrying, timing or logging one is a
host middleware (`app.use`), not a transport:

```ts
app.use(async (ctx, next) => { /* ctx.address, ctx.operation */ return next(); });
```

What that does **not** reach is the envelope itself — the encoding, the headers, the
connection. For those you are the transport, and you swap it.

**HTTP** is the engine's from start to finish: the app mounts on it with `answer(app, request)`,
and the engine's own middleware stands around it. Leaving a route out is a middleware answering
before `answer` does:

```ts
hono.delete('/api/*', (c) => c.text('Method Not Allowed', 405));
hono.all('/api/*', async (c) => (await answer(app, c.req.raw)) ?? c.notFound());
```

Where an op answers is the Frond's to say, in its `frond.config.ts` — see
[surfaces](/docs/serve/rest-graphql) for the three parts of a URL and who sets each one.
