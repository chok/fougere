# invoke

`invoke` est `useQuery`/`useCommand` sans la réactivité : la manière serveur d'appeler
une opération de Frond. Routes serveur, crons et ponts l'utilisent — même désignation,
même retour, mêmes erreurs.

```ts
// server/api/feed.xml.get.ts — un pont RSS en trois gestes : parse → invoke → formate
import Post from '@frond/blog/entities/Post';

export default defineEventHandler(async (event) => {
  const posts = await invoke<PostCard[]>(Post, 'list');
  return renderRss(posts);
});
```

## Signatures

```ts
invoke<T>(Entity, op, input?)          // désignation par classe — la forme normale
invoke<T>({ entity, op }, input?)      // forme brute, pour les ponts dynamiques
// input: { params?, query?, body? }
```

## Sémantique

- **Pas de RPC sans voyage.** `invoke` fabrique la valeur d'appel et la tend au runner :
  Frond locale → exécution mémoire directe (zéro JSON), Frond dans `remotes` → JSON-RPC
  sur le fil. Le code appelant ne sait pas lequel a eu lieu — c'est le but.
- **Le state suit.** En contexte de requête, `invoke` attache la session courante tout
  seul (contexte de requête → state d'invocation) ; hors requête, state vide ou explicite.
- **Les erreurs sont les mêmes `FougereError`** — un pont les mappe avec `toHttpError`
  s'il parle HTTP, ou les laisse se propager.

## Frontière

`invoke` est réservé aux **opérations de Frond**. Les services, `Logger`, `Config`
viennent du container (DI) — `invoke` n'est pas un service locator.

Les ponts livrés (catch-all REST, GraphQL) sont minces exactement grâce à cette forme :
*parse → invoke → formate*, rien d'autre. Écrire votre propre pont, ce sont les trois
mêmes gestes.
