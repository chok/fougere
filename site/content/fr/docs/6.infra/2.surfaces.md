# Surfaces

Les pages parlent aux Fronds par l'enveloppe. Tout le reste passe par une **surface** —
un pont mince en trois gestes : *parser* son protocole en valeur d'appel,
*[invoke](/fr/docs/client/invoke)*, *formater* le résultat en retour. Une surface ne
contient jamais de logique métier ; c'est une porte, et toutes les portes mènent aux
mêmes opérations jugées.

## REST — montée

Le module Nuxt monte un catch-all REST sous `/api/{frond}/{pluriel}` — le pluriel dérive
du nom de l'entité (`post → posts`, `category → categories`) :

| Route | Opération |
|---|---|
| `GET /api/blog/posts` | `post.list` |
| `POST /api/blog/posts` | `post.create` |
| `GET /api/blog/posts/{id}` | `post.findById` |
| `PUT · PATCH /api/blog/posts/{id}` | `post.update` |
| `DELETE /api/blog/posts/{id}` | `post.delete` |
| `POST /api/blog/posts/by-slug` | `post.bySlug` — kebab-case → camelCase ; une opération connue gagne sur un id |

Trois propriétés à connaître :

- **Même façade.** Un body REST rencontre exactement les juges que l'enveloppe impose —
  validation, refus des clés inconnues, collectors. Il n'y a pas de seconde porte plus
  laxiste.
- **Mêmes erreurs.** Les échecs se projettent par `toHttpError` : le vrai statut HTTP de
  la [table des codes](/fr/docs/business/errors), la valeur typée entière dans `data`.
- **Forme des listes.** Les résultats de `list` se sérialisent en
  `{ items, total, hasMore, endCursor }`.

## GraphQL — une projection standalone

`@fougere/schema-graphql` dérive les types, inputs et opérations CRUD Pothos depuis la
même metadata `getFields()` que lisent tous les autres adapters. Il n'est **pas monté par
le module Nuxt** — il se livre comme une projection que vous tendez au serveur GraphQL de
votre choix :

```ts
import { registerGraphQL } from '@fougere/schema-graphql';
// dérivez types/inputs/resolvers depuis vos entités, servez avec Apollo, Yoga…
// demos/schema-ecommerce fait exactement ça sous Apollo Server sur :4000
```

Honnêteté pré-release : la surface GraphQL existe comme projection de schéma avec un demo
qui tourne ; un endpoint GraphQL monté par le module Nuxt comme l'est REST n'existe pas
encore.
