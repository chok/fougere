# Ajouter Fougere à une app Nuxt existante

Fougere ne remplace pas votre app — il ajoute la couche modèle à côté. Votre routing, vos
pages, vos composants, votre style et vos routes serveur existantes continuent de
fonctionner ; le module ne revendique que ses propres portes : `/_fougere/call`
(l'enveloppe), `/api/{frond}/…` ([surface REST](/fr/docs/infra/surfaces)) et `/auth/**`
si vous activez l'auth.

## Les trois pièces

**1. Le module** — dans votre `nuxt.config.ts` existant :

```ts
export default defineNuxtConfig({
  modules: [/* vos modules */, '@fougere/nuxt'],
});
```

**2. La config** — `fougere.config.ts` à la racine
([référence complète](/fr/docs/getting-started#fougereconfigts--référence)) :

```ts
import { defineFougere } from '@fougere/core';

export default defineFougere({
  db: { dialect: 'sqlite', path: '.data/app.db' },
});
```

**3. Une première Frond** — un dossier `fronds/` avec une entité et un handler :

```
fronds/
  todo/
    package.json          ← { "name": "@frond/todo", "fougere": { "frond": "todo" } }
    entities/Todo.ts
    handlers/TodoHandler.ts
```

Bootez (`pnpm dev`) et vérifiez le log : `scanned 1 frond(s)`. Votre app est inchangée —
elle a juste gagné une couche modèle.

## Migrer feature par feature

Prenez une feature à la fois ; les anciennes routes continuent de servir le reste. Chaque
morceau de glue a son pendant Fougere, dérivé du schéma :

| Ce que vous maintenez aujourd'hui | Ce que ça devient |
|---|---|
| un schéma Zod/Yup | les champs de l'entité — [axe shape](/fr/docs/schema/entities) |
| une définition de table ou une migration | dérivée — auto-DDL depuis les mêmes champs |
| `server/api/todos.post.ts` + appel de validation | une opération de [handler](/fr/docs/business/handlers), jugée à la façade |
| l'état du formulaire + règles côté client | [`useFormFor(Todo)`](/fr/docs/client/forms) — même juge que le serveur |
| `useFetch('/api/todos')` + comptabilité de refresh | [`useQuery(Todo, 'list')`](/fr/docs/client/queries-commands) — revalidée par les commands |

Supprimez les originaux à chaque feature migrée — le but est d'avoir moins de fichiers à
synchroniser, pas une copie parallèle.

## Ce qui reste à vous

- **Pages et composants** — les primitives sont additives ; pas de layout, pas de widgets.
- **Les autres routes serveur** — tout ce qui est hors des chemins revendiqués est intact.
- **L'auth** — optionnelle. Gardez votre système si vous en avez un ; `useCurrentUser` et
  le flux session→handler demandent l'[auth Fougere](/fr/docs/client/session) activée.

## Limites honnêtes (pré-release)

- Les packages ne sont pas encore sur npm — aujourd'hui, cela fonctionne dans le
  workspace Fougere.
- Le storage est SQLite auto-DDL (Drizzle dessous). La table d'une entité appartient à
  Fougere — migrez une feature quand vous pouvez lui confier son storage, gardez votre
  accès base existant pour le reste.
