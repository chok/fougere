# Écrire la logique métier

Ce guide démarre une boutique, sans données pour l'instant : une opération, une page qui
l'appelle, un prestataire de paiement qu'on peut remplacer, et les erreurs qu'un paiement
peut renvoyer. Tout se passe dans `fronds/shop/`.

## Handlers

Un handler est une classe dans `handlers/`. Ses méthodes publiques sont ce que le reste de
l'app peut appeler.

```ts
// fronds/shop/handlers/CartHandler.ts
export default class CartHandler {
  async getTotal(): Promise<number> {
    return 4990;
  }
}
```

Rien d'autre à écrire : pas de route, pas d'enregistrement. Le fichier placé dans
`handlers/` suffit à le déclarer.

Le nom commence par un verbe, et ce verbe dit à Fougere si la méthode lit ou écrit :
`list`, `get`, `find` lisent ; `create`, `pay`, `send` écrivent. Un nom qu'il ne sait pas
lire — `total` tout seul — bloque le démarrage de l'app, avec la liste des verbes connus.
Pour garder le nom, déclarez le type dans le `frond.config.ts` de la Frond :

```ts
// fronds/shop/frond.config.ts
export default { operations: { total: { kind: 'query' } } };
```

→ [Handlers](/fr/docs/business/handlers)

## La façade

Une page n'importe pas le handler. Elle importe sa **façade**, une constante que Fougere
écrit pour chaque handler dans `@fronds/facade` :

```vue
<!-- app/pages/index.vue -->
<script setup lang="ts">
import { cart } from '@fronds/facade';

const { data: total } = await useQuery(cart, 'getTotal');
</script>

<template>
  <p>Total : {{ total / 100 }} €</p>
</template>
```

`cart` porte le type de `CartHandler` : `'getTotal'` est vérifié, et `total` est un
`number`.

Le plugin Fougere de votre hôte — `@fougere/nuxt`, `@fougere/vite`, `withFougere()` pour
Next — écrit ce module à partir de vos handlers à chaque lancement de `dev` ou de `build`.

→ [Queries & commands](/fr/docs/client/queries-commands)

## Services

Un service est une classe dans `services/` qu'un handler demande dans son constructeur.
Fougere lit le type et fournit une instance.

Un prestataire de paiement est le cas typique. Le handler demande `Payment`, et ne nomme
jamais Stripe :

```ts
// fronds/shop/services/Payment.ts
export default abstract class Payment {
  abstract charge(cents: number): Promise<{ reference: string }>;
}
```

```ts
// fronds/shop/services/StripePayment.ts
import Payment from './Payment.js';

export default class StripePayment extends Payment {
  async charge(cents: number) {
    // call Stripe here
    return { reference: 'ch_123' };
  }
}
```

```ts
// fronds/shop/handlers/CheckoutHandler.ts
import Payment from '../services/Payment.js';

export default class CheckoutHandler {
  constructor(private payment: Payment) {}

  async pay(cents: number): Promise<{ reference: string }> {
    return this.payment.charge(cents);
  }
}
```

`StripePayment extends Payment` suffit à tout brancher : `Payment` devient un **port**, et
`StripePayment` y répond. Ajoutez une deuxième implémentation — un `FakePayment` pour le
développement — et Fougere refuse de démarrer plutôt que d'en choisir une :

```
Fougere boot refused: 1 declaration(s) that do not hold:
  [port-implemented-twice] Payment
    FakePayment and StripePayment both extend Payment, and nothing says which one answers it.
    Which realization a deployment uses is not a fact about the code — state it:
    ports: { Payment: 'FakePayment' } in fougere.config.ts.
    fronds/shop/services/FakePayment.ts
```

Le choix se fait dans `fougere.config.ts`, et `CheckoutHandler` ne change pas :

```ts
export default defineFougere({
  ports: { Payment: process.env.NODE_ENV === 'production' ? 'StripePayment' : 'FakePayment' },
});
```

## Erreurs

Une opération refuse avec une `FougereError` et un code :

```ts
import { FougereError, ErrorCode } from '@fougere/core';

async pay(cents: number): Promise<{ reference: string }> {
  if (cents <= 0) {
    throw new FougereError({ code: ErrorCode.UNPROCESSABLE_ENTITY, message: 'Nothing to pay', entity: 'checkout', operation: 'pay' });
  }

  return this.payment.charge(cents);
}
```

La page sait quels codes `pay` peut renvoyer — ils font partie du type de la façade :

```ts
const pay = useCommand(checkout, 'pay');
await pay.execute({ params: { cents: 0 } }).catch(() => {});
// pay.error.value?.code: ErrorCode.UNPROCESSABLE_ENTITY | …
```

L'erreur arrive à la page avec le même code et le même message, que la Frond tourne dans
le process de l'app ou sur un autre serveur.
