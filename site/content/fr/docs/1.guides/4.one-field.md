# Un champ, partout

La boutique du [guide sur les données](/fr/docs/guides/data) a un `Product`. Ce guide lui
ajoute un champ et le suit partout où il apparaît. Vous écrivez une ligne ; le reste est une
commande et quelques requêtes.

## Avant de commencer

REST et GraphQL ne sont servis que si la config le dit. Ajoutez ceci une fois, pour tout le
projet :

```bash
pnpm add @fougere/adapter-graphql
```

```ts
// fougere.config.ts
export default defineFougere({
  adapters: { rest: true, graphql: true },
});
```

GraphQL est un paquet à part, pour qu'une app qui ne le sert pas ne l'embarque pas. Si vous
déclarez `graphql: true` sans le paquet, l'app refuse de démarrer et dit quel paquet manque.

## La ligne

```ts
// fronds/shop/entities/Product.ts
import { entity, primary, text, number, optional } from '@fougere/schema';

export default class Product extends entity({
  id: primary(),
  title: text({ min: 1, max: 200 }),
  cents: number({ min: 0 }),
  description: optional(text({ max: 500 })),
}) {}
```

C'est la seule ligne que vous écrivez.

## La base

Démarrez l'app : elle refuse, en nommant la colonne :

```
products.description — no column
```

```bash
pnpm migrate
```

l'ajoute. L'app ne modifie jamais votre base d'elle-même ; c'est `fougere migrate` qui le fait.

## REST

Le chemin REST est `/api/{frond}/{adresse, au pluriel}` :

```bash
curl http://localhost:3000/api/shop/products
```

Chaque produit a maintenant une `description`. Un `POST` avec une description de plus de
500 caractères est refusé en `400`, et le message nomme le champ.

## GraphQL

```bash
curl -X POST http://localhost:3000/graphql \
  -H 'content-type: application/json' \
  -d '{"query":"{ products { items { title description } } }"}'
```

`products` rend une page, comme REST : les lignes sont dans `items`. Le champ est aussi dans
les entrées : `createProduct(input: { …, description })` et `updateProduct`.

Pour voir tout le schéma :

```bash
npx get-graphql-schema http://localhost:3000/graphql
```

## Le formulaire

Un formulaire qui parcourt `fields` affiche le nouveau champ sans rien changer :

```vue
<script setup lang="ts">
import Product from '@fronds/shop/entities/Product.js';

const { fields, values, errors, submit } = useFormFor(Product);
</script>

<template>
  <form @submit.prevent="submit">
    <template v-for="field in fields" :key="field.name">
      <input v-model="values[field.name]" v-bind="field.attrs" :placeholder="field.label" />
      <small v-if="errors[field.name]">{{ errors[field.name] }}</small>
    </template>
    <button>Ajouter</button>
  </form>
</template>
```

Il refuse 501 caractères dans le navigateur, avec la règle du serveur. Un formulaire qui
écrit chaque champ à la main a besoin d'un champ de plus — la règle vient toujours de
l'entité.

## Ce que vous n'avez pas écrit

Pas de fichier de migration, pas de type GraphQL, pas d'entrée de création ni de mise à
jour, pas de sérialiseur REST, pas de règle de validation, pas de règle de formulaire.
Chacun est dérivé de la ligne ci-dessus, donc aucun ne peut prendre de retard sur elle.

## Le renommer plus tard

Renommer un champ est le seul changement que Fougere ne peut pas deviner : un champ parti et
un champ ajouté peuvent être un renommage, ou une suppression. Dites-le sur l'entité :

```ts
export default class Product extends entity(
  { /* … */ summary: optional(text({ max: 500 })) },
  { previous: { summary: 'description' } },
) {}
```

`pnpm migrate` renomme la colonne, et les lignes gardent leur texte. Sans `previous:`,
`fougere freeze` prévient que `description` sera supprimée avec ses données au prochain
`migrate`.
