# Démarrer

> **Pré-version.** Les paquets `@fougere/*` ne sont pas encore sur npm — aujourd'hui une
> app Fougere vit en workspace pnpm à côté des paquets du framework, et deux apps
> complètes servent de templates à copier : ce site (`site/`) et le demo phare
> (`demos/nuxt-blog`). La forme ci-dessous est celle qui est livrée. Vous avez déjà une
> app Nuxt ? [Ajoutez-y Fougere](/fr/docs/existing-app).

## La forme d'une app

Une app Fougere est une app Nuxt plus un répertoire `fronds/` et un fichier de config :

```
mon-app/
  fougere.config.ts       ← l'énoncé de l'app : persistance, auth, topologie
  nuxt.config.ts          ← modules: ['@fougere/nuxt']
  fronds/
    blog/
      package.json        ← seulement pour être importable en @frond/blog — voir plus bas
      entities/Post.ts
      handlers/PostHandler.ts
      collectors/CurrentUserCollector.ts
      seeds/Post.seed.ts
    user/                 ← pas de package.json, et une Frond quand même
      entities/User.ts
  app/
    pages/                ← des pages Nuxt ordinaires, qui parlent via les primitives
```

Tout ce qui vit sous `fronds/` est **découvert par scan** — entités, handlers, collectors
et seeds s'enregistrent par convention (emplacement du fichier + nom de classe). Aucun
fichier de câblage.

**Un dossier sous `fronds/` est une Frond.** C'est toute la règle — y être est la
déclaration. Son `package.json` répond à une autre question : comment une page écrit
l'import.

```json
{
  "name": "@frond/blog",
  "exports": { "./entities/*": "./entities/*.ts" }
}
```

Avec ce fichier (et `packages: [fronds/*]` dans `pnpm-workspace.yaml`), une page écrit
`import Post from '@frond/blog/entities/Post'`. Sans lui, la Frond est scannée exactement
pareil et ses entités s'importent par chemin relatif — ce que fait `user/` ci-dessus,
puisque rien à l'extérieur n'a besoin de la nommer.

Une clé optionnelle change quelque chose, et c'est la seule chose qu'un dossier ne sait
pas dire :

```json
{ "fougere": { "frond": "blog" } }
```

`fronds/blog-v2/` sert alors la Frond toujours appelée `blog` — ses clés d'entité, son
import `@frond/*` et toute entrée `remotes:` qui la vise ne bougent pas. Renommer sur le
disque sans renommer le contrat. Absente, le nom du dossier est le nom.

## fougere.config.ts — référence

```ts
import { defineFougere } from '@fougere/core';
import { betterAuth } from '@fougere/auth-better';
import User from './fronds/user/entities/User';

export default defineFougere({
  // Persistance. Trois formes :
  //   'sqlite'                          → mémoire côté Nuxt (resemée à chaque reload)
  //   { dialect: 'sqlite', path: '…' }  → fichier (survit aux reloads et aux deploys)
  //   false                             → pas de db
  db: { dialect: 'sqlite', path: '.data/app.db' },

  // Topologie. Une Frond listée ici reste SCANNÉE (ses entités continuent de
  // nourrir formulaires et validation en metadata) mais n'est pas hébergée
  // localement : les appels voyagent en JSON-RPC vers le process qui l'héberge.
  // Commenter la ligne → in-process.
  // remotes: { blog: 'http://127.0.0.1:4100' },

  // Auth (optionnel) — better-auth derrière une fine couche de traduction.
  auth: betterAuth({
    user: User,                             // votre entité qui étend AuthUser
    secret: process.env.AUTH_SECRET!,       // 32+ caractères
    baseUrl: process.env.SITE_URL ?? 'http://localhost:3000',
    basePath: '/auth',                      // monte /auth/** (sign-in, sign-up, sign-out…)
    trustedOrigins: ['http://localhost:3000'],
    sessionTtl: 30 * 24 * 60 * 60 * 1000,
    providers: {
      credential: { minPasswordLength: 8, autoSignIn: true },
      // google: { clientId: …, clientSecret: … },
    },
  }),
});
```

Les tables dérivent de vos entités et migrent automatiquement au boot (auto-DDL SQLite).
Les seeds tournent après la migration, par les mêmes opérations jugées que tout le reste.

## Lancer

```bash
pnpm install
pnpm dev          # scan → migre → seed → sert sur :3000
```

Le log de boot dit ce qui a été trouvé — c'est la ligne à croire :

```
INF [boot:app] scanned 2 frond(s) in 467ms
INF [boot] ready in 483ms — 2 frond(s) + auth (/auth)
```
