# Seeds

Une seed est un fichier du dossier `seeds/` d'une Frond, nommé d'après son entité, exécuté au
démarrage après la migration. C'est du code de la Frond, pas un client : ses lignes sont écrites
par le storage, comme un handler écrit — un champ fermé aux appelants (`readOnly`) et un id
choisi sont donc les siens à fixer.

```ts
// fronds/blog/seeds/Author.seed.ts
export default [
  { id: 'alice', name: 'Alice Martin', email: 'alice@example.com' },
];

// fronds/blog/seeds/Post.seed.ts
export default [
  { title: 'Bonjour', body: '…', authorId: 'alice', status: 'published', publishedAt: new Date() },
  { title: 'Encore un brouillon', body: '…', authorId: 'alice' },
];
```

## Le contrat

- **Export** : les lignes, ou `async (resolve) => lignes` quand il faut les calculer.
- **Ordre** : la cible d'un `ref()` est plantée avant ce qui la référence — `Author` avant `Post` ici.
- **Où** : une seed tourne dans le processus qui héberge le storage de son entité, et est sautée
  ailleurs. La même seed est plantée une fois, en local comme en split, sans qu'aucun code à elle
  ne le décide.
- **Idempotence** : une seed est sautée quand son entité contient déjà des lignes.
- **Ce qui reste jugé** : le storage refuse une ligne dont la forme ou la référence ne tient pas.
  Une seed n'a ni appelant ni identité — elle n'appelle pas d'opération au nom d'un utilisateur.
