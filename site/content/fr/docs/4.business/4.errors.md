# Erreurs

Un échec métier est une valeur : `FougereError` à code typé. Les handlers la lèvent ;
chaque couche au-dessus la transporte **sans la remodeler**.

```ts
throw new FougereError({
  code: ErrorCode.CONFLICT,
  message: `Le slug '${slug}' est déjà pris`,
  entity: 'post',
  operation: 'create',
  // details?: [{ path, message }]   — par champ, utilisé par VALIDATION_FAILED
  // cause?: unknown
});
```

## Les codes

| Code | Sens | Projection HTTP |
|---|---|---|
| `VALIDATION_FAILED` | entrée refusée par le juge — `details` porte les `{ path, message }` par champ | 400 |
| `UNAUTHORIZED` | pas d'identité | 401 |
| `FORBIDDEN` | identité présente, droit absent | 403 |
| `NOT_FOUND` | la chose désignée n'existe pas | 404 |
| `CONFLICT` | l'état refuse la transition ([déjà publié](/fr/docs/business/handlers#un-état-change-par-une-opération-jamais-par-une-écriture-de-champ), slug pris) | 409 |
| `SERVICE_UNAVAILABLE` | une Frond distante est injoignable | 503 |
| `INTERNAL_ERROR` | tout l'inattendu | 500 |

## Comment une erreur voyage

1. **Le handler lève** une `FougereError` — le même objet que la Frond soit locale ou distante.
2. **Appel local** — l'erreur se propage en mémoire, intouchée.
3. **Appel distant** — le transport la met en trame JSON-RPC (`code: -32000`,
   `data: { code, message, entity, operation, details? }`) et le côté appelant la
   **ravive** : ce que vous attrapez est à nouveau une `FougereError`, `details` compris.
4. **Dans une page** — `useQuery`/`useCommand` l'exposent comme `error` (une vraie
   `FougereError`) ; `useFormFor` mappe automatiquement `VALIDATION_FAILED.details` sur
   les erreurs par champ.
5. **Sur la surface REST** — `toHttpError` projette le code vers le vrai statut HTTP
   (table ci-dessus), la valeur typée entière dans `data`.

La garantie à retenir : **le navigateur reçoit le même code, le même message et les mêmes
détails par champ que le handler a levés, que la Frond soit in-process ou à trois process
de là.** Un host mort n'y fait pas exception — il remonte en `SERVICE_UNAVAILABLE` typée,
que votre page rend comme n'importe quel échec métier.

## L'ordre de jugement en pratique

Juger du moins cher au plus engageant — l'ordre que le blog de ce site utilise :

```ts
requireUser(user)        // UNAUTHORIZED
→ requireOwn(id, user)   // NOT_FOUND, puis FORBIDDEN
→ vérifs d'état          // CONFLICT (déjà publié, brouillon vide)
→ réaliser               // orm.update(…)
```
