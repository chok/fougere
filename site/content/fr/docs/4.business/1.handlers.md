# Handlers

Un handler est les opérations d'une entité. `Crud(Entity)` fournit les cinq opérations
CRUD ; **chaque méthode publique est une opération** — surchargez les défauts, ajoutez
vos verbes.

```ts
import { Crud, FougereError, ErrorCode } from '@fougere/core';
import Post from '../entities/Post.js';
import User from '../../user/entities/User.js';

export default class PostHandler extends Crud(Post) {
  /** Lecture publique : publiés seulement. */
  async list(): Promise<PostCard[]> {
    const all = await this.orm.list();
    return all.filter((p) => p.status === 'published') /* … */;
  }

  /** La transition draft→published — une opération, pas une écriture de champ. */
  async publish(id: string, user: User | null): Promise<Post> {
    if (!user) throw new FougereError({ code: ErrorCode.UNAUTHORIZED, message: 'Connectez-vous pour publier', entity: 'post', operation: 'publish' });
    const post = await this.orm.findById(id);
    if (!post) throw new FougereError({ code: ErrorCode.NOT_FOUND, message: `Post '${id}' introuvable`, entity: 'post', operation: 'publish' });
    if (post.authorId !== user.id) throw new FougereError({ code: ErrorCode.FORBIDDEN, message: 'Seul l’auteur peut publier', entity: 'post', operation: 'publish' });
    if (post.status === 'published') throw new FougereError({ code: ErrorCode.CONFLICT, message: 'Déjà publié', entity: 'post', operation: 'publish' });
    return this.orm.update(id, { status: 'published', publishedAt: new Date().toISOString() });
  }
}
```

Pas de couche service obligatoire. Un handler va de « fait tout » à « façade mince »
selon ce que le domaine exige — le choix vous appartient, pas au framework.

`this.orm` est l'accès data scopé à l'entité (`EntityOrm`) — et le seul. Lectures :
`list(options?)`, `findById(id)`, `findBy(criteria)`, `findAllBy(criteria)`. Écritures :
`create(input)`, `update(id, input)`, `delete(id)`. `output(vue)` rend un ORM scopé aux
champs d'une vue.

```ts
await this.orm.findBy({ slug });                    // la ligne qui correspond
await this.orm.findAllBy({ authorId: user.id });    // toutes celles qui correspondent
await this.orm.list({ where: { status: 'published' }, limit: 20, orderBy: 'createdAt' });
```

Il écrit librement — l'axe lifecycle se réalise ici (tampons, défauts), le jugement a déjà
eu lieu à la façade. Ce qui sort est jugé de nouveau au passage : une valeur que le shape
refuse n'atteint jamais le storage.

## Les quatre règles de binding

Fougere lit votre signature (parse AST au boot) et lie chaque paramètre depuis
l'invocation — dans cet ordre :

| # | Le paramètre ressemble à | Lié depuis |
|---|---|---|
| 1 | un type qui a un [Collector](/fr/docs/business/collectors) (`user: User \| null`) | le `collect(ctx)` du collector |
| 2 | `ctx: InvocationContext` | l'invocation entière |
| 3 | un primitif (`id: string`, `page: number`) | `params[nom]`, puis `query[nom]` — coercé en number/boolean |
| 4 | tout le reste (`input: PostDraft`) | le `body` de la requête |

Deux conséquences du parser AST-only (pas de type checker) :

- **Épelez les types.** `user: User | null` se lie ; `user: CurrentUser` (un alias) est
  invisible et ne lie rien.
- **Toute méthode publique est joignable par le fil.** Les helpers vivent hors de la
  classe (fonctions de module) — un `private` ne retire pas une méthode de la surface
  d'opérations.

## Validation des entrées

Quand le type d'un paramètre est une classe de schéma (entité ou vue), la façade valide
le body du fil contre elle **avant** votre méthode — une entrée invalide n'atteint jamais
votre code ; l'appelant reçoit `VALIDATION_FAILED` avec les détails par champ. Une vue
`partial()` valide en mode patch.

### Les clés inconnues sont refusées

Une clé hors contrat est une erreur, jamais un retrait silencieux : un body
`{ …, status: 'published' }` contre une vue qui ne déclare pas `status` ressort en
`VALIDATION_FAILED` (`status: Unknown field`) avant votre méthode. Un body qui passe le
juge est donc exactement le contrat — vous pouvez l'étaler dans l'ORM sans projection
préalable. Le client émet des bugs (`titel`) ou des attaques, pas des variantes légitimes
— les deux méritent le 400 ; et le même juge tourne dans `useFormFor`, donc le refus a
lieu dans le navigateur avant le réseau.

## Un état change par une opération, jamais par une écriture de champ

`publish()` ci-dessus est le motif de tout ce qui a des états — une commande, un
abonnement, un ticket. Quatre déclarations, et chacune ferme une porte différente :

```ts
// l'entité — le jeu de valeurs, et celle avec laquelle elle naît
status: readOnly(oneOf('draft', 'published', { default: 'draft' })),
```

```ts
// le handler — le passage, et le refus
async publish(id: string): Promise<Post> {
  const post = await this.orm.findById(id);
  if (post.status === 'published') {
    throw new FougereError({ code: ErrorCode.CONFLICT, message: 'Already published',
      entity: 'post', operation: 'publish' });
  }
  return this.orm.update(id, { status: 'published' });
}
```

- **`oneOf`** borne les valeurs. Trois lecteurs en font quelque chose sans qu'on le leur
  dise : le formulaire rend un `<select>`, le DDL émet `CHECK status in (…)`, GraphQL
  déclare un type enum.
- **`{ default: 'draft' }`** est l'état initial — une règle de création sur
  [l'axe lifecycle](/fr/docs/schema/entities), donc personne ne le fournit.
- **`readOnly`** ferme le champ aux clients : `boundary.in` vaut `closed`, donc `status`
  est absent de toute vue d'entrée. Un corps qui le porte est refusé en clé inconnue.
- **L'opération nommée** est la seule entrée, et `CONFLICT` est son refus —
  [409](/fr/docs/business/errors), parce que c'est l'état qui dit non, pas l'entrée.

**Ce qui n'est pas garanti, et où.** L'ordre des passages ne vit que dans cette méthode. La
base accepte n'importe quelle valeur du jeu, donc un `UPDATE` en SQL brut — ou un autre
handler qui appelle `this.orm.update(id, { status })` — passe à côté. Un juge n'est
incontournable que là où tout écrivain le rencontre, et celui-ci n'y est pas. Il n'y a donc
pas de graphe d'états à déclarer dans Fougere : le champ énonce quelles valeurs existent,
l'opération énonce comment on atteint l'une d'elles.

## Vue de sortie

Le deuxième argument de `Crud` nomme la vue émise. Deux formes, qui ne portent pas aussi
loin :

```ts
Crud(Post, { list: PostCard })   // list rend des cartes, le reste rend Post
Crud(Post, PostPublic)           // tout le handler rend PostPublic
```

Par opération, c'est une **déclaration** : l'ORM rend toujours la ligne entière et la
façade projette en sortie — vos autres opérations et vos juges lisent encore les champs
que la carte omet.

Pour tout le handler, c'est un **scoping** : l'ORM injecté lui-même est restreint. Avec un
second fichier de handler, cela donne des surfaces par audience — `handlers/PostHandler.ts`
(complet) et `handlers/public/PostHandler.ts` (restreint).
