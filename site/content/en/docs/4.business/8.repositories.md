# Repositories

[`EntityOrm`](/docs/business/orm) is a port: generic gestures, no flavour of domain. "The
loud readings" is not one of them, so that query ends up spelled at the call site, in the
middle of the calculation it feeds. A query with no home squats in the answer.

`Repository(Entity)` gives it one:

```ts
// repositories/ReadingRepository.ts
export default class ReadingRepository extends Repository(Reading) {
  loud(): Promise<Reading[]> {
    return this.orm.findAllBy({ loud: true });
  }
}
```

The handler then asks the question, and never spells the storage:

```ts
// handlers/ReadingHandler.ts
export default class ReadingHandler {
  constructor(private readingRepository: ReadingRepository) {}

  async loud() { return this.readingRepository.loud(); }
}
```

`repositories/` is scanned like `services/` — the class registers as a provider, and its
constructor dependencies resolve by type as anywhere else.

## Write none and you lose nothing

Every entity gets a repository whether or not you wrote the file: the boot registers the
guarded ORM under the same key. So a handler may ask for one before anyone writes the
class, and declaring one later wins under that key — exactly as a `Crud` operation
redefined in a subclass wins over the prefab's.

Giving the ORM itself as the default was shorter and wrong. `repo.orm` would then exist
only when someone had written the file, and the two forms would differ exactly where the
convention promises they do not. The default holds the port and adds nothing, so
`repo.orm.list()` reads the same either way.

That default is a guarantee, not something to reach for. When an entity has no named
query, ask for its port and say so plainly:

```ts
constructor(private orm: EntityOrm<Node>) {}
```

::warning
Injection matches the **name of the type written on the parameter**, and the container key
is `<Entity>Repository`. A declared class must therefore be called `ReadingRepository` —
not `Readings`, not `ReadingQueries` — or nothing resolves it.
::

## It is not a door

A repository has no façade, so nothing it carries is reachable from the wire. That is what
makes it free to hold whatever the domain asks — but it also means a **judge does not
belong here**. Rules stay in the [handler](/docs/business/handlers), the one place a
refusal cannot be walked around.

Writes are still judged, because they go through the port: a value the entity forbids is
refused whether a repository or a handler issued it.
