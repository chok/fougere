# Errors

A domain failure is a value: `FougereError` with a typed code. Handlers throw it; every
layer above transports it **without reshaping it**.

```ts
throw new FougereError({
  code: ErrorCode.CONFLICT,
  message: `Slug '${slug}' is already taken`,
  entity: 'post',
  operation: 'create',
  // details?: [{ path, message }]   — per-field, used by VALIDATION_FAILED
  // cause?: unknown
});
```

## The codes

| Code | Meaning | HTTP projection |
|---|---|---|
| `VALIDATION_FAILED` | input refused by the judge — `details` carries per-field `{ path, message }` | 400 |
| `UNAUTHORIZED` | no identity | 401 |
| `FORBIDDEN` | identity present, right absent | 403 |
| `NOT_FOUND` | designated thing does not exist | 404 |
| `CONFLICT` | state refuses the transition ([already published](/docs/business/handlers#a-state-changes-through-an-operation-never-through-a-field-write), slug taken) | 409 |
| `SERVICE_UNAVAILABLE` | a remote Frond is unreachable | 503 |
| `INTERNAL_ERROR` | anything unexpected | 500 |

## How an error travels

1. **Handler throws** `FougereError` — the same object whether the Frond is local or remote.
2. **Local call** — the error propagates in memory, untouched.
3. **Remote call** — the transport frames it as a JSON-RPC error (`code: -32000`,
   `data: { code, message, entity, operation, details? }`) and the client side
   **revives it**: what you catch is a `FougereError` again, `details` included.
4. **In a page** — `useQuery`/`useCommand` expose it as `error` (a real `FougereError`);
   `useFormFor` maps `VALIDATION_FAILED.details` onto per-field errors automatically.
5. **On the REST surface** — `toHttpError` projects the code to the real HTTP status
   (table above), the full typed value in `data`.

The guarantee to remember: **the browser receives the same code, message and per-field
details the handler threw, whether the Frond was in-process or three processes away.** A
dead host is not an exception to this — it surfaces as a typed `SERVICE_UNAVAILABLE`, which
your page renders like any other domain failure.

## Judging order in practice

Judge cheap-and-honest first — the same order the site's own blog uses:

```ts
requireUser(user)        // UNAUTHORIZED
→ requireOwn(id, user)   // NOT_FOUND, then FORBIDDEN
→ state checks           // CONFLICT (already published, empty draft)
→ realize                // orm.update(…)
```
