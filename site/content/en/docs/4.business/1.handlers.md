# Handlers

A handler is the operations of one entity. `Crud(Entity)` gives the five CRUD operations;
**every public method is an operation** — override the defaults, add your own verbs.

```ts
import { Crud, FougereError, ErrorCode } from '@fougere/core';
import Post from '../entities/Post.js';
import User from '../../user/entities/User.js';

export default class PostHandler extends Crud(Post) {
  /** Public reading: published only. */
  async list(): Promise<PostCard[]> {
    const all = await this.orm.list();
    return all.filter((p) => p.status === 'published') /* … */;
  }

  /** The draft→published transition — an operation, not a field write. */
  async publish(id: string, user: User | null): Promise<Post> {
    if (!user) throw new FougereError({ code: ErrorCode.UNAUTHORIZED, message: 'Sign in to publish', entity: 'post', operation: 'publish' });
    const post = await this.orm.findById(id);
    if (!post) throw new FougereError({ code: ErrorCode.NOT_FOUND, message: `Post '${id}' not found`, entity: 'post', operation: 'publish' });
    if (post.authorId !== user.id) throw new FougereError({ code: ErrorCode.FORBIDDEN, message: 'Only the author can publish', entity: 'post', operation: 'publish' });
    if (post.status === 'published') throw new FougereError({ code: ErrorCode.CONFLICT, message: 'Already published', entity: 'post', operation: 'publish' });
    return this.orm.update(id, { status: 'published', publishedAt: new Date().toISOString() });
  }
}
```

There is no mandatory service layer. A handler scales from "does everything" to "thin
façade" as the domain demands — that choice is yours, not the framework's.

`this.orm` is the entity-scoped data access (`EntityOrm`): `list(options?)`,
`findById(id)`, `create(input)`, `update(id, input)`, `delete(id)`. It writes freely —
the lifecycle axis is realized here (stamps, defaults), the judging already happened at
the façade.

## The four binding rules

Fougere reads your method signature (AST parse at boot) and binds each parameter from the
invocation — in this order:

| # | Parameter looks like | Bound from |
|---|---|---|
| 1 | a type with a [Collector](/docs/business/collectors) (`user: User \| null`) | the collector's `collect(ctx)` |
| 2 | `ctx: InvocationContext` | the whole invocation |
| 3 | a primitive (`id: string`, `page: number`) | `params[name]`, then `query[name]` — coerced to number/boolean |
| 4 | anything else (`input: PostDraft`) | the request `body` |

Two consequences of the parser being AST-only (no type checker):

- **Spell types out.** `user: User | null` binds; `user: CurrentUser` (a type alias) is
  invisible and binds nothing.
- **Every public method is wire-reachable.** Helpers must live outside the class (module
  functions) — a `private` keyword does not hide a method from the operation surface.

## Input validation

When a parameter's type is a schema class (entity or view), the façade validates the wire
body against it **before** your method runs — invalid input never reaches your code; the
caller gets `VALIDATION_FAILED` with per-field details. A `partial()` view validates as a
patch.

### Unknown keys are refused

A key outside the contract is an error, never a silent drop: a body
`{ …, status: 'published' }` against a view that does not declare `status` comes back as
`VALIDATION_FAILED` (`status: Unknown field`) before your method runs. A body that passes
the judge therefore *is* the contract — you can spread it into the ORM without projecting
it first. A client can only emit strangers by bug (`titel`) or by attack — both deserve
the 400; and the same judge runs in `useFormFor`, so the refusal happens in the browser
before the network.

## Output scoping

`Crud`'s second argument names the view the ops emit, and it has two spellings that do
different things.

**A view per op** — a declaration, nothing more:

```ts
export default class PostHandler extends Crud(Post, { list: PostCard }) {}
```

`list` returns cards, every other op returns the whole post. The handler's ORM **stays
full**: an op that needs the entire row still works, and a judge still reads the fields
the card omits. The façade is what projects each result onto the view declared for its op.

**A view for the whole handler** — this one scopes the injected ORM:

```ts
export default class PublicPostHandler extends Crud(Post, PostPublic) {}
```

Every read returns only the fields the view declares. Combined with a second handler file,
this gives per-audience surfaces — e.g. `handlers/PostHandler.ts` (full) and
`handlers/public/PostHandler.ts` (restricted).

Pick the per-op form when only the listing needs to slim down; the handler-wide form when
the whole handler speaks to a restricted audience.
