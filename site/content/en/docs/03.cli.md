# The CLI

`@fougere/cli` composes a workspace, hosts a Frond in its own process, and invokes an
operation from a shell. It is itself a Fougere app — its commands are entities with
handlers under `fronds/`, which is why every flag below is a field on a schema and gets
judged like any other input.

> **Pre-release.** Not on npm yet, so today it runs from the workspace
> (`node packages/cli/dist/bin.js …`). The commands and flags below are what ships.

## `fougere new` — compose a workspace

```bash
fougere new shop --frond blog --app nuxt
```

Two phases in dependency order: the Fronds (your domains), then the apps that consume
them. It produces a pnpm workspace:

```
shop/
  fougere.config.ts          ← db, auth, topology
  pnpm-workspace.yaml        ← packages: [fronds/*, apps/*]
  fronds/blog/               ← the domain
    entities/Post.ts
    handlers/PostHandler.ts
  apps/nuxt/                 ← the consumer
    nuxt.config.ts
    app/pages/index.vue
```

| Flag | What it does |
|---|---|
| `--frond blog,api:catalog` | Fronds to add — `template:name` renames; the template name is the default name |
| `--app nuxt:web` | same, for apps |
| `--bare` | the empty shell, nothing composed |
| `--local` | link `@fougere/*` to a local Fougere checkout (development) |
| `--force` | overwrite an existing directory |

**Stated or guided.** With `--frond`/`--app` nothing is asked — the only form a script, a
CI job or an agent can drive. With neither, and a TTY, it prompts template by template.
The guided flow needs that TTY and would hang without one, which is why stating wins.

What the generated Frond teaches is the point: an entity that owns its data, two views
derived from it (`NewPost` for what a client may propose, `PostCard` for what a list
emits), and a real business operation next to the CRUD:

```ts
export class NewPost extends Post.pick('title', 'body') {}

export default class PostHandler extends Crud(Post) {
  async create(input: NewPost): Promise<Post> { … }

  /** The draft→published transition — an operation, not a field write. */
  async publish(id: string): Promise<Post> { … }
}
```

Contract first, projection second — not CRUD with a form bolted on.

## `fougere serve` — one Frond, its own process

```bash
fougere serve blog --port 4100
```

Boots that Frond alone and exposes it over JSON-RPC on `POST /_fougere/call`. The
consuming app names it in `remotes:` and nothing else changes — this is the
[gradient](/docs/infra/gradient), from the shell.

It does **not** follow `remotes:` itself: a host *is* the Frond, it does not route back
out.

> `serve()` binds `127.0.0.1` by default, and that default is what protects it: a split
> receiver reads identity off the wire. Do not expose it on a public interface.

## `fougere call` — invoke an operation

```bash
fougere call post.list
fougere call post.create --title "Hello" --body "…"
```

Rides the same call contract as every other consumer — the envelope, the judges, the
typed errors. A `VALIDATION_FAILED` in a shell is the same value a page receives.

## `fougere sync` — consume a remote Frond

```bash
fougere sync blog --from http://blog-service:4100
```

Asks the host `rpc.discover`, and writes local entity files rebuilt from the
[cards](/docs/schema/card) it answers with:

```ts
// .fougere/remotes/blog/entities/Post.ts — generated
import { reconstruct } from '@fougere/schema';
const Post = reconstruct({ /* the card, verbatim */ });
export default Post;
```

The rebuilt class validates locally: judgment is never a network round-trip. It also
writes `.fougere/remotes.json`, which the Nuxt module reads to alias `@frond/blog` — so
pages import a remote Frond's entity exactly as they import a local one.

Only entities the host actually **serves** come back: an entity with no façade declares
no operation, so publishing its shape would hand a caller the structure of tables it can
never reach.

## `fougere graph` — read the model

```bash
fougere graph
```

Prints the entity graph — each entity, what it references, how many reference it — and,
past six entities, the natural domain clusters it finds:

```
  Post → Author, Category (2 incoming)
  Author
```

This is the instrument the [shortest path](/docs/concepts/shortest-path) page describes,
in its first form: a reading anyone can render in a minute, where the same judgment
phrased in model terms took a senior and an hour.

## `fougere build-frond` — publish a Frond's entities

```bash
fougere build-frond blog
```

Compiles `fronds/blog/entities/**` to `dist/` with type declarations and points the
Frond's `package.json` at them. What a consumer in another repository installs when the
Frond moves out — the [organizational dimension](/docs/infra/gradient#where-the-code-lives)
of the gradient.
