# The identity card

An entity declared in TypeScript does not travel: it is a class, with thunks and closures.
Its **card** travels — a JSON document describing the same thing, from which a consumer
rebuilds a living schema.

It is the structural counterpart of Standard Schema: where `~standard` is the live, opaque
"I can validate" interface, the card is the transparent, serialisable description that
crosses the wire.

```ts
import { describe, reconstruct } from '@fougere/schema';

const card = describe(Post);       // schema → JSON document
const Rebuilt = reconstruct(card); // document → living schema (validate + from)
```

The two functions are dual and **single**: `describe` is the one canonical serialiser
(adapters call it instead of hand-rolling copies), `reconstruct` the one reconstructor.
What crosses is reconstituted **at the consumer** — validation is never a network
round-trip.

## The structure

The card is a valid JSON Schema document. The `shape` axis **is** that vocabulary, so its
keywords sit at the field's top level; the three other axes live under the `x-fougere`
extension key.

```jsonc
{
  "title": "post",
  "type": "object",
  "properties": {
    "id": {
      "type": "string",
      "x-fougere": {
        "role": { "primary": true },
        "lifecycle": { "create": { "generate": "cuid2" } }
      }
    },
    "title": { "type": "string", "minLength": 3, "maxLength": 120 },
    "status": { "type": "string", "enum": ["draft", "published"] },
    "publishedAt": {
      "type": ["string", "null"],
      "format": "date-time",
      "x-fougere": { "lifecycle": { "update": "forbidden" } }
    },
    "secret": { "type": "string", "x-fougere": { "boundary": { "out": "closed" } } }
  },
  "required": ["title", "status"],
  "x-fougere-version": 1,
  "x-fougere-vendor": "fougere"
}
```

A nullable field folds into the union `type: ["T", "null"]` — nullability is shape, hence
plain JSON Schema. An embedded object (`json(Entity)`) carries its nested `properties` and
`required`, themselves shape-only.

## The three axes under `x-fougere`

The normal forms **are** the wire form: named tokens, pure JSON. There is no descriptor
twin to maintain — they travel verbatim.

| key | values | what it states |
|---|---|---|
| `role.primary` | `true` | identity — the system owns it |
| `role.unique` | `[["slug"], ["listId","docId"]]` | the unique constraints this field is a member of — one member list each, members named. A lone field is the degenerate case: a constraint of one. The DDL emits them |
| `role.index` | `true` | storage constraint — the DDL emits it |
| `role.relation` | `{ to, kind: 'one'\|'many', onDelete? }` | `to` is a **name**, not an inlined schema |
| `lifecycle.create` | `{ value }` \| `'now'` \| `{ generate }` \| `'optional'` | who writes at creation, and when |
| `lifecycle.update` | `'now'` \| `'forbidden'` | who writes on update |
| `boundary.in` | `'closed'` \| `{ decode }` | read-only, or a named inbound conversion |
| `boundary.out` | `'closed'` \| `{ encode }` | write-only, or a named outbound conversion |

An absent key means open: no `lifecycle.create` means the caller must supply the value; no
`boundary` means identity in both directions.


Only an **explicitly declared** boundary is emitted. The default derived from the shape (a
`format: date-time` field decodes to a `Date`) is not carried: it is re-derived on
reconstruction. Convention over configuration, all the way onto the wire.

`role.unique` **always names its members** on the wire, a single-field constraint included
(`[["slug"]]`). In memory a lone `unique()` carries the empty list — a field does not know
its own key, which is given by the object `entity({...})` receives — and `describe` resolves
it on the way out. So you never have to know which field a group hangs on: the pair
`(listId, docId)` appears in full on `listId` **and** on `docId`, which is what lets you
recover the constraint without reading the whole entity.

## `required` does not mean what JSON Schema thinks

This is the one place the card departs from the standard reading, and you need to know it
to produce one.

`required` lists **the names a caller must supply at creation** — those no `lifecycle.create`
rule answers the absence of, and that are not a `many` relation (absent → `[]`). It is
narrower than JSON Schema's `required`, which is context-free and answers "what is always
present when read?".

The consequence not to miss: a **nullable field stays required**. The caller may supply
`null`, it may not omit the key. Presence and nullability are two distinct axes.

## The bundle — several entities, relations included

`describeSet` produces a self-contained `$defs` document, each entity under its lowercased
name — exactly the name a `relation.to` carries.

```ts
const bundle = describeSet({ post: Post, author: Author });
const { post, author } = reconstructSet(bundle);
```

A relation is a **pointer**, never an inlined sub-schema: `Post → Author → Post` is two
references, not infinite nesting. `reconstruct` alone leaves relations as bare names;
`reconstructSet` resolves them, and the rebuilt `to()` hands back the real target entity —
what adapters need.

## The honest losses

A card is data. What is live does not cross, and saying so beats letting it be discovered:

- **a relation becomes a name.** The `() => Author` thunk is gone; `reconstructSet` restores
  it inside a bundle, not beyond one.
- **a custom generator or conversion travels by NAME**, re-resolved against the consumer's
  registry. An unknown name fails **loudly and locally** ("unknown generator") rather than
  silently at the neighbour's.

This is why the axes never accept a closure: a function would vanish without a sound at
serialisation, and the remote frond would pay for it.

## `rpc.discover` — a whole app's card

A host answers the reserved `rpc.discover` operation with what it hosts: its fronds, their
entities, the operations each façade exposes, and every schema's card.

```jsonc
{
  "fronds": [{
    "name": "blog",
    "entities": [{ "name": "post", "ops": ["list", "findById", "publish"], "schema": { … } }]
  }]
}
```

This is what the doublure router asks on the first call it cannot place: the key declared
in `remotes` is only a label for an address — **the card decides which entities live
behind it**.

## Writing a Frond elsewhere

None of this assumes TypeScript. A frond written in another language joins the topology if
it honours three things:

1. **the wire** — `POST /_fougere/call`, JSON-RPC 2.0, `method = "entity.op"`;
   see [The gradient](/docs/infra/gradient).
2. **the card** — `rpc.discover` returns the envelope above, `x-fougere-version: 1`.
3. **the error vocabulary** — a whole `FougereError` in `error.data`, its `code` a
   [semantic code](/docs/business/errors); the `-32000` integer stays the JSON-RPC spec's.

The consumer then rebuilds the schema and **judges locally**: the same rules, without ever
having seen a line of the other side's language.

`demos/rust-frond/` is one, in Rust — one entity, three operations, no `entity({...})`
class anywhere.
