# Entities

An entity is a class extending the `entity()` factory. The class **is** the type, the
validator and the metadata — declared once, projected everywhere.

```ts
import { entity, primary, text, ref, auto, oneOf, date, readOnly, optional } from '@fougere/schema';
import Author from './Author.js';

export default class Post extends entity({
  id: primary(),
  slug: text({ min: 1, max: 80 }),
  title: text({ min: 1, max: 160 }),
  body: optional(text()),
  authorId: ref(Author),
  createdAt: auto(),
  status: readOnly(oneOf('draft', 'published', { default: 'draft' })),
  publishedAt: readOnly(optional(date())),
}) {}
```

The class name is the identity: `Post.name` names the SQLite table, the GraphQL type, the
registration key (`post`) and the DI match. `entity()` takes no name argument — nothing is
declared twice.

## Field vocabulary

Value fields:

| Helper | Type | Options |
|---|---|---|
| `text(opts?)` | `string` | `min`, `max`, `pattern`, `format`, `default` |
| `email(opts?)` | `string` | `text` options minus `format` |
| `url(opts?)` | `string` | `text` options minus `format` |
| `number(opts?)` | `number` | `min`, `max`, `integer`, `default` |
| `bool(opts?)` | `boolean` | `default` |
| `date()` | `Date` | — |
| `oneOf(...values, opts?)` | union of literals | `default` |
| `list(item, opts?)` | `T[]` | item is any field |

Role fields:

| Helper | Meaning |
|---|---|
| `primary()` | primary key, generated — also wraps a field: `primary(text())` |
| `ref(Entity)` | foreign key (`string`); accepts `() => Entity` for cycles |
| `many(Entity)` | one-to-many — role only, no column |
| `unique(f)` | no two rows carry the same value — a constraint the **database** enforces |
| `indexed(f)` | reads filter on this often — emits `CREATE INDEX`, changes no answer |

The bounds a shape declares — `oneOf`, `min`, `max` — are not only judged at the door.
They are emitted as `CHECK` constraints, so a write that never passes through the façade
meets them too: a raw query, another process, a person at a prompt. `pattern` and
`format` stay at the façade — regex dialects diverge between engines, and a constraint
that means something different per database is worse than none.

Some facts are about a pair, not a field. "A book appears once in a list" is true of
`(listId, docId)` and of neither alone, so it is declared on the entity:

```ts
class ListBook extends entity({
  id: primary(),
  listId: ref(List),
  docId: text(),
}, {
  unique: [['listId', 'docId']],
}) {}
```

The database enforces it, which is the only place it is enforceable: a handler that
checks and then writes issues two round trips, and a concurrent request fits between
them. A derivation that drops a member of the group drops the group — `(listId)` alone
would state something stronger than you wrote.

Lifecycle fields:

| Helper | Meaning |
|---|---|
| `auto()` | stamped at create (`createdAt`) — never client-written |
| `updated()` | re-stamped at every update (`updatedAt`) |

Wrappers (compose around any field):

| Wrapper | Axis | Effect |
|---|---|---|
| `optional(f)` | shape | may be absent; `T \| null` |
| `nullable(f)` | shape | may be `null`, must be present |
| `immutable(f)` | lifecycle | writable at create, forbidden on update |
| `readOnly(f)` | boundary | never crosses inward — output only |
| `writeOnly(f)` | boundary | never crosses outward — input only (passwords) |

Wrappers nest: `readOnly(optional(date()))` is a server-owned, possibly-absent date.

> **`unique` is the one rule the judge cannot enforce.** `Post.validate()` sees a single
> input, never the other rows — so a duplicate passes validation and is refused by the
> database, as a driver error rather than a per-field one. That is not a gap: uniqueness
> is a fact about the *table*, so the table is what owns it. A `primary()` field needs
> neither word — it is already both.

## The four axes

Every field carries four orthogonal axes — this is the model all adapters read:

| Axis | Question | Read by |
|---|---|---|
| **shape** | what values are valid? (the shape *is* JSON Schema) | validation, forms, SQL column, GraphQL scalar |
| **role** | what part does it play? (`primary`, `ref`, `many`) | DDL (PK/FK), relations |
| **lifecycle** | who writes it, when? (`auto`, `updated`, `immutable`) | ORM realization, constructor relaxation |
| **boundary** | which way does it cross the API? (`readOnly`, `writeOnly`) | io projections `inputFields` / `outputFields` |

**Validation judges, storage realizes.** The façade judges client input against the shape
and boundary axes — a client writing `status` (readOnly) is refused. Handlers then write
freely through the ORM, which realizes the lifecycle axis — stamping `createdAt`, applying
defaults. One declaration, two disciplines. The judge is itself a projection of the
shape axis — a *normative, embedded* one: it ships with the class and every other
projection must agree with it (see [Philosophy](/docs/concepts/philosophy#embedded-or-externalized)).

> The judge **refuses** unknown keys — `Unknown field`, never a silent drop. An input
> that passes is exactly the contract (see
> [Handlers](/docs/business/handlers#unknown-keys-are-refused)).

## Entity.validate

The validation engine is edge-safe (`@cfworker/json-schema`) — the same judge runs in the
browser and in the handler:

```ts
Post.validate(input)
// → { success: true, data }                                    valid
// → { success: false, errors: [{ path: 'title', message }] }   invalid, per-field
```

`new Post(data)` builds a **trusted** instance — no validation, relaxed constructor
(generated/auto fields optional at construction, always present on the type).
