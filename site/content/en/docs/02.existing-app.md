# Add Fougere to an existing Nuxt app

Fougere does not replace your app — it adds the model layer next to it. Your routing,
pages, components, styling and existing server routes keep working; the module only
claims its own doors: `/_fougere/call` (the envelope), `/api/{frond}/…`
([REST surface](/docs/infra/surfaces)) and `/auth/**` if you enable auth.

## The three pieces

**1. The module** — in your existing `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  modules: [/* your modules */, '@fougere/nuxt'],
});
```

**2. The config** — `fougere.config.ts` at the root
([full reference](/docs/getting-started#fougereconfigts--reference)):

```ts
import { defineFougere } from '@fougere/core';

export default defineFougere({
  db: { dialect: 'sqlite', path: '.data/app.db' },
});
```

**3. A first Frond** — a `fronds/` directory with one entity and one handler:

```
fronds/
  todo/
    package.json          ← { "name": "@frond/todo", "fougere": { "frond": "todo" } }
    entities/Todo.ts
    handlers/TodoHandler.ts
```

Boot (`pnpm dev`) and check the log: `scanned 1 frond(s)`. Your app is unchanged —
it just gained a model layer.

## Migrate feature by feature

Take one feature at a time; the old routes keep serving the rest. Each piece of glue has
a Fougere counterpart the schema derives:

| You maintain today | It becomes |
|---|---|
| a Zod/Yup schema | the entity's fields — [shape axis](/docs/schema/entities) |
| a table definition or migration | derived — auto-DDL from the same fields |
| `server/api/todos.post.ts` + validation call | a [handler](/docs/business/handlers) operation, judged at the façade |
| form state + client-side rules | [`useFormFor(Todo)`](/docs/client/forms) — same judge as the server |
| `useFetch('/api/todos')` + refresh bookkeeping | [`useQuery(Todo, 'list')`](/docs/client/queries-commands) — revalidated by commands |

Delete the originals as each feature lands — the point is fewer files to keep in sync,
not a parallel copy.

## What stays yours

- **Pages and components** — the primitives are additive; no layout, no widgets.
- **Other server routes** — anything outside the claimed paths is untouched.
- **Auth** — optional. Keep your own system if you have one; `useCurrentUser` and the
  session-to-handler flow need [Fougere auth](/docs/client/session) to be enabled.

## Honest limits (pre-release)

- Packages are not on npm yet — today this works inside the Fougere workspace.
- Storage is SQLite auto-DDL (Drizzle underneath). An entity's table is owned by
  Fougere — bring a feature in when you can hand its storage over, keep your existing
  database access for the rest.
