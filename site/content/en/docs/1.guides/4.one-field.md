# One field, everywhere

The shop from [the data guide](/docs/guides/data) has a `Product`. This guide adds one field to
it and follows that field to every place it shows up. You write one line; the rest is a
command and a few requests.

## Before you start

REST and GraphQL are served only when the config says so. Add this once, for the whole
project:

```bash
pnpm add @fougere/adapter-graphql
```

```ts
// fougere.config.ts
export default defineFougere({
  adapters: { rest: true, graphql: true },
});
```

GraphQL is a separate package so that an app that does not serve it does not ship it. If you
declare `graphql: true` without the package, the app refuses to start and says which package
is missing.

## The line

```ts
// fronds/shop/entities/Product.ts
import { entity, primary, text, number, optional } from '@fougere/schema';

export default class Product extends entity({
  id: primary(),
  title: text({ min: 1, max: 200 }),
  cents: number({ min: 0 }),
  description: optional(text({ max: 500 })),
}) {}
```

That is the only line you write.

## The database

Start the app and it refuses, naming the column:

```
products.description — no column
```

```bash
pnpm migrate
```

adds it. The app never changes your database on its own; `fougere migrate` is the command
that does.

## REST

The REST path is `/api/{frond}/{address, plural}`:

```bash
curl http://localhost:3000/api/shop/products
```

Each product now has a `description`. A `POST` with a description longer than 500
characters is refused with `400`, and the message names the field.

## GraphQL

```bash
curl -X POST http://localhost:3000/graphql \
  -H 'content-type: application/json' \
  -d '{"query":"{ products { items { title description } } }"}'
```

`products` returns a page, like REST: the rows are in `items`. The field is also in the
inputs: `createProduct(input: { …, description })` and `updateProduct`.

To see the whole schema:

```bash
npx get-graphql-schema http://localhost:3000/graphql
```

## The form

A form that loops over `fields` shows the new field with nothing to change:

```vue
<script setup lang="ts">
import Product from '@fronds/shop/entities/Product.js';

const { fields, values, errors, submit } = useFormFor(Product);
</script>

<template>
  <form @submit.prevent="submit">
    <template v-for="field in fields" :key="field.name">
      <input v-model="values[field.name]" v-bind="field.attrs" :placeholder="field.label" />
      <small v-if="errors[field.name]">{{ errors[field.name] }}</small>
    </template>
    <button>Add</button>
  </form>
</template>
```

It refuses 501 characters in the browser, with the rule the server uses. A form that writes
each input by hand needs one more input — the rule still comes from the entity.

## What you did not write

No migration file, no GraphQL type, no create or update input, no REST serializer, no
validation rule, no form rule. Each one is derived from the line above, so none of them can
fall behind it.

## Renaming it later

Renaming a field is the one change Fougere cannot guess: a field gone and a field added may
be a rename, or a drop. Say it on the entity:

```ts
export default class Product extends entity(
  { /* … */ summary: optional(text({ max: 500 })) },
  { previous: { summary: 'description' } },
) {}
```

`pnpm migrate` renames the column, and the rows keep their text. Without `previous:`,
`fougere freeze` warns that `description` will be dropped with its data at the next
`migrate`.
