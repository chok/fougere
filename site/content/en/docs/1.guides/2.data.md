# Store your data

The shop from [the first guide](/docs/guides/business-logic) returns a total written in
the code. This guide stores real products: an entity, a repository, and a form to add
them.

## Entities

An entity is a class in `entities/` that describes one kind of data:

```ts
// fronds/shop/entities/Product.ts
import { entity, primary, text, number } from '@fougere/schema';

export default class Product extends entity({
  id: primary(),
  title: text({ min: 1, max: 200 }),
  cents: number({ min: 0 }),
}) {}
```

From this class Fougere builds the `products` table, the validation of every input, and
the fields of a form.

`Crud(Product)` gives a handler the five usual operations — `list`, `get`, `create`,
`update`, `delete`:

```ts
// fronds/shop/handlers/ProductHandler.ts
import { Crud } from '@fougere/core';
import Product from '../entities/Product.js';

export default class ProductHandler extends Crud(Product) {}
```

## Migrations

The table does not exist yet, and the app does not create it for you: it refuses to start,
and says what is missing.

```
Fougere boot refused: the database is behind the entities (1):
  products — no table
  Read the plan: fougere migrate — then write it: fougere migrate --apply
```

`pnpm migrate` — `fougere migrate --apply` — creates it. Run it each time an entity gains a
field; the boot tells you when.

A rename is declared on the entity, and the rows follow:

```ts
export default class Product extends entity(
  { id: primary(), name: text(), cents: number({ min: 0 }) },
  { previous: { name: 'title' } },
) {}
```

`fougere migrate` shows `products: title → name`, and `--apply` renames the column.

## Repositories

A repository is where an entity's rows are read and written. Every entity has one already;
write the class when a query deserves a name:

```ts
// fronds/shop/repositories/ProductRepository.ts
import { Repository } from '@fougere/core';
import Product from '../entities/Product.js';

export default class ProductRepository extends Repository(Product) {
  cheapest(): Promise<Product[]> {
    return this.list({ orderBy: 'cents', limit: 5 });
  }
}
```

A repository is a service like `Payment`: a handler asks for it by type.

```ts
// fronds/shop/handlers/CartHandler.ts
import ProductRepository from '../repositories/ProductRepository.js';

export default class CartHandler {
  constructor(private products: ProductRepository) {}

  async getTotal(): Promise<number> {
    const products = await this.products.list();

    return products.reduce((sum, product) => sum + product.cents, 0);
  }
}
```

## Forms

`useFormFor` builds a form's state from the entity. It checks in the browser what the
server checks, so an empty title or a negative price is refused before anything is sent:

```vue
<script setup lang="ts">
import Product from '@fronds/shop/entities/Product.js';

const { values, errors, submit, loading } = useFormFor(Product);
</script>

<template>
  <form @submit.prevent="submit">
    <input v-model="values.title" />
    <p v-if="errors.title">{{ errors.title }}</p>
    <input v-model.number="values.cents" type="number" />
    <p v-if="errors.cents">{{ errors.cents }}</p>
    <button :disabled="loading">Add</button>
  </form>
</template>
```

`submit` calls `create`. After it succeeds, every page listing products refreshes on its
own.
