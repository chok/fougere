# invoke

`invoke` is `useQuery`/`useCommand` without the reactivity: the server-side way to call a
Frond operation. Server routes, crons and bridges use it — same designation, same return,
same errors.

```ts
// server/api/feed.xml.get.ts — an RSS bridge in three moves: parse → invoke → format
import Post from '@frond/blog/entities/Post';

export default defineEventHandler(async (event) => {
  const posts = await invoke<PostCard[]>(Post, 'list');
  return renderRss(posts);
});
```

## Signatures

```ts
invoke<T>(Entity, op, input?)          // designation by class — the normal form
invoke<T>({ entity, op }, input?)      // raw form, for dynamic bridges
// input: { params?, query?, body? }
```

## Semantics

- **No RPC without travel.** `invoke` builds the call value and hands it to the runner:
  local Frond → direct memory execution (zero JSON), Frond in `remotes` → JSON-RPC on the
  wire. The calling code cannot tell which happened — that is the point.
- **State follows.** In request context, `invoke` attaches the current session by itself
  (request context → invocation state); outside a request, state is empty or explicit.
- **Errors are the same `FougereError`s** — a bridge maps them with `toHttpError` if it
  speaks HTTP, or lets them propagate.

## Boundary

`invoke` is for **Frond operations only**. Services, `Logger`, `Config` come from the
container (DI) — `invoke` is not a service locator.

The bridges that ship (REST catch-all, GraphQL) are thin exactly because of this shape:
*parse → invoke → format*, nothing else. Writing your own bridge is the same three moves.
