# Forms

`useFormFor` is the form **contract** — state, validation, submission, per-field error
mapping. It renders nothing: the page owns the widgets, the contract owns the mechanics.

```vue
<script setup lang="ts">
import Post from '@frond/blog/entities/Post';

const { values, errors, submit, loading, error } = useFormFor<{ id: string }>(Post);

async function onSubmit() {
  const created = await submit();          // null when a judge rejected
  if (created) navigateTo(`/blog/edit/${created.id}`);
}
</script>

<template>
  <form @submit.prevent="onSubmit">
    <UFormField label="Title" :error="errors.title">
      <UInput v-model="values.title" />
    </UFormField>
    <p v-if="error">{{ error.message }}</p>          <!-- non-validation failure -->
    <UButton type="submit" :loading="loading" />
  </form>
</template>
```

## Signature

```ts
useFormFor<T>(EntityOrView, options?)
// options: {
//   op?: string                        command the submit rides — default 'create'
//   initial?: Record<string, unknown>  edit mode: the loaded entity
//   params?: Record<string, string>    designation of the target — edit mode: { id }
// }
```

Returns:

| Key | Type | Notes |
|---|---|---|
| `fields` | `FormField[]` | derived from the io axes — server-owned fields never appear |
| `values` | `reactive` record | initialized from `initial` — see the note on defaults |
| `errors` | `reactive` record | field path → message |
| `submit` | `() => Promise<T \| null>` | see cycle below |
| `loading` | `Ref<boolean>` | |
| `error` | `Ref<FougereError \| null>` | **non-validation** failure (conflict, dead host) |
| `valid` | `ComputedRef<boolean>` | no current field errors |

Edit mode composes with a query:

```ts
const { data: post } = await useQuery<Post>(Post, 'findById', { params: { id } });
const form = useFormFor(Post, { op: 'update', params: { id }, initial: post.value ?? undefined });
```

## The submit cycle

1. **Local pre-judgment** — `Entity.validate(payload)` runs in the browser with exactly
   the rules the handler enforces (one declaration, both sides). Rejections land in
   `errors` without a round-trip; `submit()` returns `null`.
2. **The command** — the payload rides `useCommand(Entity, op)`, so a success triggers
   the entity link: mounted queries revalidate.
3. **Remote judgment** — a `VALIDATION_FAILED` coming back is mapped onto `errors` by
   `path`, exactly like the local judge. **The form never knows who judged.**
4. Anything else (`CONFLICT`, `SERVICE_UNAVAILABLE`…) lands in `error`, untouched.

## What the form will not do

- **Render** — widgets and layout are app-land, deliberately.
- **Show server-owned fields** — `readOnly` fields are excluded by the io projection; a
  status is displayed as a badge from the loaded data, not editable as an input.
- **Guess labels** — field labels are your i18n's business; the metadata gives stable
  keys (entity + field name) to hang them on.
- **Pre-fill declared defaults** — and that is the axes, not an omission. A `default` in a
  field is a `lifecycle.create` rule: **the storage realizes it**, the same way it stamps
  `createdAt`. So `oneOf('draft', 'published', { default: 'draft' })` leaves the form
  field empty and comes back `'draft'` from the write. Pre-filling it in the browser would
  make the client state a fact it does not own — and two places would then answer "what is
  the default", which is the drift a single declaration exists to kill. Want it visible
  before the write? Pass it in `initial` — that is the app choosing, explicitly.
