# Session

The session is resolved server-side. It is then hydrated into the page, injected into
handlers, and sent to remote Fronds.

## useCurrentUser

```ts
const { user, refresh } = useCurrentUser();
// user:    Ref<User | null> — resolved during SSR, hydrated with the page: zero extra requests
// refresh: () => Promise<void> — re-read after sign-in/out
```

```vue
<template>
  <UButton v-if="user" :to="localePath('/blog/new')" :label="$t('nav.write')" />
  <UButton v-else :to="localePath('/login')" :label="$t('nav.signIn')" />
</template>
```

Route protection is an ordinary Nuxt middleware reading the same session — Fougere does
not add a parallel guard system.

## The auth surface

`fronds: { auth: betterAuth({ … }) }` in `fougere.config.ts` ([reference](/docs/getting-started#fougereconfigts--reference))
mounts better-auth under `basePath` — the endpoints your pages call directly:

```ts
await $fetch('/auth/sign-up/email', { method: 'POST', body: { name, email, password } });
await $fetch('/auth/sign-in/email', { method: 'POST', body: { email, password } });
await $fetch('/auth/sign-out',      { method: 'POST', body: {} });
// then: await refresh()
```

Your `User` entity extends `AuthUser` — better-auth's fields plus yours:

```ts
import { AuthUser } from '@fougere/auth-better';
import { oneOf, optional } from '@fougere/schema';

export default class User extends AuthUser.extend({
  role: optional(oneOf('admin', 'editor', 'reader')),
}).anchor() {}
```

The named subclass matters: the scanner registers the entity as `User`, and DI matches
`user?: User` by that checked type.

`betterAuth()` is a frond named `auth`: it holds `session`, `account` and `verification` —
`user` too when you name none — so its tables migrate and its writes are judged like any other
frond's. It carries its [extension](/docs/infra/lifecycle), which rises only in the process
serving the frond: it declares `user` and `session` on the call's state and registers the
runtime under `AUTH`, which is what the host mounts. A process that `only:` leaves it out of
starts no engine and migrates no session table.

> Do not place pages under the auth `basePath`: the server catch-all uses `/auth/**`.
> This site serves its forms at `/login` and `/register` for that reason.

## One resolution, three readers

| Reader | How identity arrives |
|---|---|
| the page | hydration — `useCurrentUser()`, zero requests |
| a handler | invocation state → a [Collector](/docs/business/collectors) fills `user?: User` |
| a remote Frond | state is sent with the call — its collectors receive the same user |

The browser cannot write this state: it is built server-side from the request context
([Queries & commands](/docs/client/queries-commands#the-wire--and-ssr)).
